# NeoMIFES プロジェクト凍結レポート (2026-09-11)

> **本ファイルを読んでいる人へ:** これは「今、このプロジェクトはどういう状態で、なぜ止まっていて、再開するには何を確認すべきか」を1つのファイルで把握できるようにした文書である。コンテキストを一切持たないセッション(または数ヶ月ぶりに戻ってきたユーザー本人)が、他のドキュメントを読み漁らなくてもここだけで現在地を掴めることを目標にしている。詳細が必要な箇所は個別ドキュメントへリンクする。

## 1. 結論 (最初に読むこと)

**NeoMIFESは2026-09-11、ユーザーの判断により開発を凍結した。** 「完全終了」ではなく「一旦停止、条件が整えば再開」という位置づけであり、コード・ドキュメント・issueは全て現状のまま(削除せず)保存されている。

- **凍結理由 (要約):** 当初の差別化構想だった「AI親和」機能(Phase 9)は、Copilot/Cursor/Windsurf/Continue.dev等の専門企業による急速なコモディティ化で個人開発が勝負できる領域ではないと判断した。AI無しで秀丸エディタ/MIFESという既存の枯れたエディタと同じ土俵(通常のテキストエディタとしての完成度)で比較すると、現時点のNeoMIFESに明確な優位性は無い。
- **再開条件:** 「NeoMIFESの優位性が考えられた時」(ユーザー自身の言葉)。§6に再開判断の具体的な着眼点を記録した。
- **技術資産は無駄になっていない:** 2ヶ月・400コミットで構築したエンジン層(Piece Table/10GB対応/Direct2D描画/プラグインホスト等)は実測で確かな成果であり、再開時の土台としてそのまま使える。

---

## 2. 凍結に至った経緯

2026-09-11のセッションで、ユーザーが実機でNeoMIFESを操作し(このセッション自体もその過程で3件のスクロールバグ〔WI-44/45/46、§4参照〕を発見・修正した)、以下の流れで凍結の判断に至った。

1. **ユーザーからの問い:** 「開発着手から数ヶ月経過したが秀丸エディタやMIFESと比較するとだいぶ使い勝手や機能面において劣っていると感じる。このまま開発を継続してクレジット消費するより、既存の枯れたエディタを使った方が良いのではないか？」
2. **Claude Codeの回答:** ギャップを正直に認めた上で、「秀丸に機能で追いつく」ことを目指すか、「AI親和という差別化」を目指すかで判断が変わる、とユーザーへ方向性を確認した。
3. **ユーザーの回答:** AI親和を検証したいので継続意思はあるが、AI(Phase 9)が未着手なのは想定外——実装困難だから止まっているのか、と質問。
4. **Claude Codeの回答:** 未着手の理由は技術的困難さではなく、①CLAUDE.md自身の原則(「エディタ本体はAI無しでも100%動作しなければならない」、本体未完成時にAIを積むのは矛盾)によるフェーズ順序の後回し、②2026-08-23の合意によるスコープ凍結(差別化機能追加に終わりが見えなくなったため線引きした)、の2段階の意図的判断だったと説明。また、AIプラグインの土台となるプラグインホスト(L2層、DLLホットロード)は既にPhase 8で実装・テスト済みであること、`master_roadmap.md` §9にAIプラグインの詳細設計(Claude/OpenAI/Gemini/Ollama対応、Copilot型補完、RAG、エージェント等)が既に存在することを伝えた。
5. **ユーザーの結論:** AI実装は専門企業によりコモディティ化しておりレッドオーシャンのため個人開発には向かない。単に秀丸の代替として使いたいが、現状秀丸の方が優れておりNeoMIFESに優位性が無い。
6. **Claude Codeの回答:** その認識に同意した上で、優位性が無い理由は「機能が足りないから」ではなく「秀丸が30年かけて築いた『当たり前に壊れない』という信頼の土台にまだ到達していないから」だと補足(同日発見された3件の基本操作バグを例示)。「今すぐ秀丸から乗り換えたい」が目的なら継続の経済合理性は薄いが、技術資産は無駄になっていないため「完全終了」より「凍結」が合理的、と提案。
7. **ユーザーの決定:** 「ひとまず凍結する。今後NeoMIFESの優位性が考えられた時に再開する。これまでの開発経緯を漏れなくコンテキストが失われても持続可能なようにドキュメントファイル一式に記載のうえ、プロジェクトを一旦閉じよ。」

## 3. 何を達成したか (2026-07-15〜2026-09-11、約2ヶ月・400コミット)

### 3.2 実測性能 (公称目標との対比)

- 起動時間: **実測29.3ms**(目標≤300ms、約10倍のマージン)
- スクロール: **avgFrame 16.6ms(≈60fps)**、10GB実ファイルでの定常スクロールでも同水準(p50=16.67ms/p95=16.84ms)
- 10GBファイル: Private memory **1.22GB**(対策前は20GB超で強制終了)、初回インデックス構築**26.99秒**(対策前113.7秒)
- 100万回Undo: ヘッドレスプローブで実測、`AddBuffer`のappend-only設計により線形増加・非加速を確認

### 3.3 実装済み機能 (レイヤ別)

- **L7 UI Shell:** メニューバー・タブUI・ステータスバー(6パート)・行番号ガター・ウィンドウクローム・右クリックメニュー・複数ウィンドウ(独立プロセスではなく単一プロセス複数`MainWindow`方式)
- **L6 Application Shell:** `EditorSession`/`Workspace`/`SessionManager`、設定システム(`core::Settings`、`settings.json`)、キーバインド(4プリセット: neomifes/hidemaru/sakura/vscode)、自動保存/クラッシュ復旧/最近使ったファイル
- **L5 Editor Core:** Command/Undoスタック、複数カーソル、矩形選択(列編集)、検索/置換(独立ダイアログ、秀丸風)
- **L4 Rendering:** Direct2D/DirectWrite、TextLayoutCache、折り返し(word wrap)、ミニマップ、IME完全対応(インライン変換・候補ウィンドウ・下線描画)、テーマ(ダーク/ライト/ハイコントラスト)、シンタックスハイライト(tree-sitter、多言語)、コードフォールディング、Breadcrumb/Sticky scroll、Git diffインライン表示、縦横スクロールバー(設定でON/OFF可)
- **L3 Document Engine:** Piece Table(RB-tree)、mmap + Lazy Decode(`OriginalBuffer`)、10GBファイル対応
- **L3 Search/Grep:** RE2正規表現、CRLF対応、専用ベンチマーク付き
- **L3 Encoding:** 自動判定・変換
- **L2 Plugin Engine:** DLLホットロード、サンドボックス化されたCore API(`NeomifesCoreApi`)、サンプルプラグイン動作確認済み(このAI凍結判断の土台として重要 — §6参照)
- **差別化モード (Phase 10):** ログ解析モード、CSVモード(グリッド編集・フィルタ・列固定・セル単位クリック編集)、JSON/XML Treeモード(XPath自前実装)
- **Git統合 (Phase 11.1):** ステータス表示・Gitペイン(変更ファイル一覧)・Diffビュー(インライン統合diff)
- **アクセシビリティ:** 簡易UI Automation対応(`ui::TextSurfaceAccessible`、フルTextPattern実装ではなく簡易アナウンス実装)

### 3.4 品質・検証体制

- 単体+統合テスト: **1621件**(凍結時点)、全てDebug/Release/ASan/UBSanの4構成でgreen
- CI: GitHub Actions、5ジョブ(release/debug/asan/ubsan/clang-tidy)
- 静的解析: clang-tidy新規指摘0件を各WI完了時に確認する運用が定着
- 実機ドッグフーディングを各WIの完了条件として重視(「プロセスが生存していた」ではなく実際の操作結果を確認する運用、CLAUDE.md §11)

## 4. 何が未達か・なぜ止まっているか

### 4.1 意図的にスコープ外とした項目 (2026-08-23合意、`docs/handoff/RESUME_HERE.md`参照)

- **Phase 9 (AIプラグイン):** 本レポートの凍結理由そのもの。`master_roadmap.md` §9に詳細設計(Claude/OpenAI/Gemini/Ollama対応、Copilot型ゴーストテキスト補完、RAG、マルチモデル比較、エージェント)を凍結保存済み。土台となるプラグインホスト(L2層)は実装・テスト済み
- **Phase 11.2 LSP完全実装 / Phase 11.3 マクロ(Lua+JS+秀丸互換):** 未着手
- **Git統合の高度機能:** Blame/Commit/Branch切替/3-Way Merge
- **`master_roadmap.md` §12.3の元22項目フル版:** NVDA/JAWS専門認証・本物のAuthenticode証明書配布・SBOM/CVE継続運用・自動更新機構など

### 4.2 ユーザー判断待ち・対象外確定の項目

- [`authenticode_certificate_not_acquired.md`](../issues/authenticode_certificate_not_acquired.md) (P1): 署名機構自体は自己署名証明書で実装済み、実配布には本物の証明書購入が必要(ユーザー判断待ち)
- [`csv_per_cell_index_memory_scaling.md`](../issues/csv_per_cell_index_memory_scaling.md) (P1、部分対応): CSVモードの10GB規模メモリ最適化(遅延インデックス化)は再設計コストが大きいためユーザー承認のもと対象外確定

### 4.3 「機能は揃っているが信頼性がまだ秀丸に及ばない」問題

凍結直前(2026-09-11)のセッションだけで、ユーザーの実機ドッグフーディングにより以下3件の**基本操作レベル**のバグが新規発見・修正された(WI-44/45/46、詳細は`docs/design/build_plan.md`該当セクション参照):

1. 短い文書でカーソルが2行目に達するだけで1行目が不要にスクロールアウトする
2. IME変換中のテキストがウィンドウ幅を超えても水平スクロールが追従しない(修正後も「全角文字の実描画幅の過小評価」という第2の不備が発覚し二段階で修正)
3. マウスホイールによる水平スクロールが実装されていなかった(存在しない機能だった)

**これが「秀丸との比較で優位性が無い」ことの本質だと考えられる。** JSON/XML Tree・CSVグリッド・Git統合ペインのような秀丸のマクロ/プラグインでは自然には出せない機能は既に存在するが、基本操作の粗さが残っている限り、ユーザーはその付加価値を体感する前に離脱してしまう。機能の広さでは無く、「秀丸が30年かけて築いた当たり前の信頼性」に追いつくことが本質的な課題であり、これには終わりの見えにくい磨き込みの時間がかかる。

## 6. 再開する場合の判断基準

ユーザーは「NeoMIFESの優位性が考えられた時」を再開条件とした。以下は再開を検討する際に確認すべき具体的な着眼点(判断は将来のユーザー自身が行う、ここでは材料の提示のみ):

- **AI周辺の状況変化:** Copilot/Cursor等の競合が寡占的なままか、あるいは「プライバシー重視・オフライン動作・Windows ネイティブ」等、個人開発でも取れるニッチが新たに見えてきたか。`master_roadmap.md` §9の設計(特にローカルLLM対応)は、クラウドAI各社と直接競合しない差別化軸として再評価の余地がある
- **秀丸/MIFES側の変化:** 開発終了・値上げ・Windows新バージョンへの追従遅延など、既存の「枯れたエディタ」の優位性が相対的に揺らぐ事態が起きたか
- **NeoMIFES固有の需要:** 10GBファイル対応・CSVグリッド編集・JSON/XML Tree・Git統合ペインのような、既に実装済みの機能群がユーザー自身の実務で明確に必要になったか(既存の秀丸+マクロ/プラグイン構成では代替コストが高い場面が実際に発生したか)
- **信頼性ギャップを埋める意思:** §4.3で述べた「基本操作の磨き込み」に十分な時間を投じる意思があるか。これはAIの有無と独立した、地道な作業量の問題

## 7. 再開する場合の技術的手順

1. **`CLAUDE.md`を読む。** 凍結notice(本レポートへのリンク)が先頭にあるはずなので、まずそこで凍結が解除されたことをユーザーへ確認する
2. **`docs/design/build_plan.md` §0(コールドスタート手順)を実行する。** 5〜10分でビルド環境・現在地を確認できる
3. **ローカルビルド検証:** `docs/design/build_plan.md` §4.3の手順(Debug/Release/ASan/UBSanのフル4構成、2026-09-11時点で全1621件green)
4. **`docs/history/TIMELINE.md`の末尾(本レポート直前のセッション記録)から遡って経緯を追う**
5. **次の作業単位の選定:** CLAUDE.md §11の3つの正典ソース(要件定義書の未達項目/`master_roadmap.md` §12.3の未達項目/`gap_analysis.md`のP0/P1)に加え、本レポート§4の未達項目一覧を出発点にする
